1Meet the Script

The Script: where your code lives

A Script is where you write code. Think of a note you put in someone's pocket. The person with the note follows it. In Roblox you put the note inside a block. Then that block follows it. Things in Roblox can hold other things inside them, like a bag holds books.

2Say hello

Make the computer talk to you

When your Script opens, delete everything in it first. Then type this, exactly like this:

print("hello")

print does not use a printer! It makes the computer write a message in a window called the Output. Open it from the View tab. This is how the computer talks back to you.

Your turn
  1. Type print("hello").
  2. Press Play.
  3. Look at the Output window. Do you see "hello"?
  4. Now change "hello" to your name. Play again.

You just told a computer what to do! 🎉

🍌 BRAIN SNACK: Code is just instructions

Code is not magic or maths homework. It is a list of instructions in a language the computer understands. A recipe is code for cooking. Directions to your house are code for walking. That is the whole secret.

3The big idea

The biggest idea in games: EVENTS

Here is the most important idea you will ever learn in game coding: "WHEN something happens, DO something." That is called an event. When the bell rings, students go to class. When the matatu hoots, everyone hurries. When you score, the crowd cheers. Every game is built from thousands of these little rules.

4Line 1

Line 1: tell the code which block is yours

Now the real thing, one tiny line at a time. Delete the print line. Type:

NEW LINE
local part = script.Parent

Read it like a sentence: "script is me, this note. Parent is the thing I am tucked inside, my Part. Let us call it part so it is easy to talk about."

Careful: capital P in Parent! The computer thinks parent and Parent are two different words, like Simba the lion and simba the neighbour's cat.

Your turn
  1. Type this one line yourself.
  2. Go slow. Get the capital P right.
5Line 2

Build the "do it" box (a function)

Now what should HAPPEN. A function is just a little box of instructions with a name, like a labelled tin in the kitchen. Ours is labelled onTouch, and inside is one step: paint the block red. Add these three lines under Line 1:

NEW LINES
local function onTouch(otherPart)
    part.Color = Color3.fromRGB(255, 0, 0)
end

The middle line means "part, change your Color to red." Color3.fromRGB(255, 0, 0) is a recipe for a colour: 255 red, 0 green, 0 blue = pure RED. The end is the lid that closes the box.

Your turn
  1. Type all three lines.
  2. Say out loud what is inside the onTouch box.

Answer: one step, paint the block red.

🍌 BRAIN SNACK: A function is a named box of steps

Writing a function does not DO anything yet. It just stores the steps, like writing a recipe does not cook the chapati. Someone still has to say "NOW use it!" That someone is next.

6Line 3

Connect the wires!

We have the WHEN (touching) and the DO (the onTouch box). Now wire them together. Add this last line:

NEW LINE
part.Touched:Connect(onTouch)

In kid language: "Hey part! You have an alarm called Touched that rings when anything touches you. When it rings, open the onTouch tin and do what is inside." Connect is exactly that: plugging a wire from the alarm to the box.

Capital T in Touched, capital C in Connect.

Your whole script is now 5 lines:

local part = script.Parent

local function onTouch(otherPart)
    part.Color = Color3.fromRGB(255, 0, 0)
end

part.Touched:Connect(onTouch)
Your turn
  1. Add the last line.
  2. Read all 5 lines out loud, like a story.

"My block is called part. Here is a box called onTouch that turns it red. When part is touched, do onTouch."

🍌 BRAIN SNACK: The computer obeys EXACTLY

A computer is the world's most obedient but most literal friend. It never guesses. Touched works; touched means nothing to it. When code fails, it is almost always one tiny letter, not you being bad at this.

7Play it

Press Play. Touch it. Watch it obey. 🟥

The moment. Press Play and walk your character straight into your block. Did it turn RED the instant you touched it? THAT WAS YOUR CODE. The block noticed you. Your world just came alive, and your five lines did it.

🏃
Your turn
  1. Press Play. Walk into your block.
  2. Did it turn red? 🟥
  3. Press Stop. Change the colour numbers. Try (0, 255, 0) for green.
  4. Play again and see the new colour.

You are changing code now, like a real coder!

Nothing happened? Tap here, do not panic
  1. Is the Script INSIDE the Part? Check the Explorer. The Script must sit under your Part (Step 1), not next to it. If it is in the wrong place, hold the left mouse button on the Script and drag it onto the Part, then let go.
  2. Look for red text in the Output window. Red text is the computer HELPING you, not scolding. It points at the exact line with the problem. Check that line for a tiny typo: a small letter that should be capital (Touched, Connect, Parent, Color).
🍌 BRAIN SNACK: "When X, do Y" is EVERYTHING

Lava that hurts? When touched, do damage. A door? When clicked, do open. A coin? When touched, do add points and vanish. You now know the pattern behind almost every game mechanic. Everything ahead is just new Xs and new Ys.
